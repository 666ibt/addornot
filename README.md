# compsheet — автосборка конкурентного листа

Собирает конкурентный лист (сравнительную таблицу КП поставщиков) в Excel:
на вход — шаблон `.xlsx` с одним готовым блоком сравнения и каталог с
коммерческими предложениями в любых форматах, на выходе — заполненный по тому
же шаблону файл с рабочими формулами, пересчитанный и проверенный.

```bash
build-competitive-sheet \
  --template template.xlsx \
  --offers ./offers/ \
  --config purchase.yaml \
  --out result.xlsx
```

## Что делает

| Этап | Модуль | Суть |
|---|---|---|
| 1. Чтение файлов | `compsheet/extract/textract.py` | PDF с текстовым слоем → `pdftotext`; скан → `pdftoppm` + `tesseract`; `.doc/.docx` → LibreOffice, а при «поломанной» конвертации — рендер в PDF → OCR |
| 2. Извлечение | `compsheet/extract/llm.py` | один запрос к Claude на поставщика, со всеми его файлами (для сканов — сразу изображения страниц), ответ ограничен JSON-схемой |
| 3. Проверка | `compsheet/review.py` | сводка по каждому поставщику с пометкой происхождения каждого значения; правка отдельных полей без перезапуска извлечения |
| 4. Курсы | `compsheet/fx.py` | курсы из конфига или с cbu.uz; неизвестная валюта останавливает запуск, а не пишет 0 |
| 5. Генерация | `compsheet/template/` | геометрия блока читается из шаблона, формулы генерируются заново по ролям строк |
| 6. Валидация | `compsheet/validate.py` | пересчёт в headless LibreOffice, поиск `#REF!`/`#NAME?`/…, сверка итогов с суммой из самого КП, экспорт в PDF |

Ключевой принцип: **«извлечено из документа» и «предположено системой» разделены
на каждом уровне** — в JSON (`source: extracted | assumed | missing | user`), в
сводке проверки (`✓ ~ ✗ ✎`) и в самом файле (комментарии к ячейкам). Файл с
ошибками формул не выдаётся: он сохраняется как `<out>.invalid.xlsx`, а команда
завершается с кодом 4.

## Установка

```bash
./setup-system-deps.sh      # LibreOffice (writer + calc), poppler, tesseract с языками
export ANTHROPIC_API_KEY=…  # для извлечения через Claude
pip install -e .
```

Проверить окружение: `build-competitive-sheet --check-env`.

Языковые пакеты OCR проверяются до запуска: без `tesseract-ocr-rus` tesseract
молча выдаёт транслитерацию вместо русского текста, поэтому его отсутствие —
ошибка, а не предупреждение (обойти можно флагом `--allow-missing-ocr-langs`).

## Конфиг закупки

```yaml
base_currency: UZS
vat_rate: 0.12
suppliers_per_block: 2          # сколько поставщиков в одном блоке

fx:                             # курсы к базовой валюте
  USD: 12950.0
  EUR: 14100.0

spec:                           # закупаемая номенклатура
  - description: "Резервуар горизонтальный стальной РГС-50, 50 м3"
    qty: 4
    unit: "шт"
    match: ["резервуар горизонтальный", "РГС-50"]

# при необходимости — свои метки строк шаблона
label_patterns:
  lead_time: ["срок\\s+поставк", "срок изготовления"]
```

Ничего товарно-специфичного в коде нет: и структура блока, и список полей
берутся из шаблона и конфига.

## Как читается шаблон

`compsheet/template/parse.py` находит первый блок по меткам из конфига и
определяет: колонку меток, колонки каждого поставщика (по merge-паттерну),
строки параметров, шапку таблицы номенклатуры, строку-образец позиции, строки
итогов, высоты строк и стили каждой ячейки. Дальше эта структура используется
как функция-шаблон: блок печатается столько раз, сколько нужно, а строка
позиции повторяется по числу позиций спецификации — всё, что ниже, съезжает
вместе с merge-диапазонами и стилями.

Формулы **не копируются из шаблона, а генерируются по роли строки** — именно это
чинит две типовые поломки исходных файлов:

* итоги суммируют весь диапазон позиций (`SUM(F18:F22)`), а не одну строку;
* пересчёт в местную валюту берёт курс из реально заполненной таблицы
  (`=E21*VLOOKUP(E11;compsheet_fx;2;0)`), а не из пустого диапазона.

Используются только функции, которые понимает LibreOffice: `SUM`, `IF`,
`VLOOKUP`, `INDEX`/`MATCH`, `SUMPRODUCT`. Никаких `XLOOKUP`/`FILTER`/`UNIQUE`.

Дополнительно на выходе: сбрасывается «вписать всё в одну страницу» по высоте
(иначе многоблочный лист сжимается до нечитаемого масштаба), расставляются
разрывы страниц по границам блоков, повторяется шапка листа на каждой странице.

## Проверка и правки

Перед генерацией показывается сводка; данные сохраняются рядом с результатом
как `result.offers.json`. Поправить поле и пересобрать, ничего не извлекая заново:

```bash
build-competitive-sheet --template template.xlsx --config purchase.yaml \
  --from-json result.offers.json --out result.xlsx \
  --set 'Бета.currency=UZS' \
  --set 'Бета.item1.unit_price=235000000'
```

Адресация: `Компания.поле` или `Компания.itemN.поле`; компанию можно указать
фрагментом названия или номером из сводки. Значение помечается как `user` и
больше не считается догадкой системы.

В интерактивном режиме (без `--yes`, в терминале) то же самое доступно
командой `п Компания.поле=значение` прямо в диалоге проверки.

## Что попадает в предупреждения

* файл не открылся / докачался не полностью — с именем файла и причиной;
* поставщик не предложил позицию — в лист пишется «— не предложено —», кол-во и
  цена нулевые, чтобы формулы не падали;
* поставщик посчитал цену за 1 единицу вместо требуемого объёма — сравнение по
  итоговой сумме некорректно;
* нет курса для валюты предложения — запуск останавливается;
* не указано, входит ли НДС в цену;
* сумма позиций расходится с итогом, напечатанным в самом КП, больше чем на 1%.

## Тесты

```bash
python3 -m pytest tests -q
```

79 тестов, включая golden-прогон: `fixtures/` содержит шаблон и набор КП,
покрывающий текстовый PDF, скан без текстового слоя, читаемый `.docx`, `.docx` с
поломанной кодировкой, поставщика из двух файлов, недокачанный файл и
поставщика, приславшего цену за одну единицу. Прогон идёт до конца — сборка,
пересчёт в LibreOffice, сверка вычисленных сумм с числами из документов.
Фикстуры пересоздаются скриптами `fixtures/make_template.py` и
`fixtures/make_offers.py`.

Тесты не ходят в сеть: они используют офлайн-извлечение (`--no-llm`).

## Офлайн-режим `--no-llm`

Регулярочный экстрактор для запусков без ключа API. Он заметно слабее: числа
разбирает только из аккуратных таблиц, а строку, которую не удалось разобрать
однозначно (не сходится «цена × количество = сумма»), помечает как непрочитанную
и просит заполнить вручную — вместо того чтобы записать правдоподобную ерунду.
Для сканов это штатный исход; основной путь для них — мультимодальный запрос к
Claude с изображениями страниц.
