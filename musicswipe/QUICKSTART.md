# Запуск на своём iPhone за 10 минут

Пошагово, с нуля. Компьютер подойдёт любой — Windows, Linux или Mac.

---

## Часть 1. Бэкенд (один раз, ~5 минут)

Без него приложение запустится, но не сможет ничего показать.

### 1.1. Создать проект

Зарегистрируйтесь на [supabase.com](https://supabase.com), нажмите **New project**.
Придумайте пароль к базе, выберите регион поближе. Проект поднимается 1–2 минуты.

### 1.2. Залить схему и функции

```bash
npm install -g supabase
cd musicswipe

supabase login                        # откроет браузер
supabase link --project-ref <ref>     # ref виден в адресе панели: supabase.com/dashboard/project/<ref>
supabase db push

supabase functions deploy import-playlist
supabase functions deploy recommend
supabase functions deploy rebuild-profile
```

### 1.3. Включить вход

В панели Supabase:

* **Authentication → Sign In / Providers → Email** — включить.
* Там же **Anonymous sign-ins** — включить. Без этого не сработает кнопка
  «Продолжить без регистрации».

### 1.4. Забрать URL и ключ

Нужны два значения. Есть два способа их достать.

**Способ А — через терминал.** Не зависит от того, как сейчас выглядит панель:

```bash
supabase projects list                          # покажет REFERENCE ID ваших проектов
supabase projects api-keys --project-ref <ref>
```

Вторая команда выведет таблицу с ключами. Нужна строка **`anon`**.

URL собирается из того же ref по шаблону — придумывать ничего не надо:

```
https://<ref>.supabase.co
```

**Способ Б — в панели.** Откройте проект, слева внизу шестерёнка
**Project Settings**, дальше:

* **Project URL** — на странице **Data API** (в старых версиях панели —
  просто **API**), в самом верху.
* **Ключ** — на странице **API Keys**. Нужен тот, что помечен `anon` `public`.
  Если у вас новый формат ключей, он называется **publishable** и начинается
  на `sb_publishable_` — такой тоже подойдёт.

**Какой ключ брать нельзя.** На той же странице лежит `service_role`
(в новом формате — `secret`, `sb_secret_...`). Он обходит все правила доступа
и пускает к чужим данным. В приложение попадает только `anon` / `publishable`:
он для того и сделан, чтобы уехать на клиент.

### 1.5. Проверить, что значения рабочие

Прежде чем возиться с телефоном, убедитесь, что бэкенд отвечает:

```bash
cd musicswipe
SUPABASE_URL=https://<ref>.supabase.co \
SUPABASE_ANON_KEY=<ваш ключ> \
node supabase/scripts/smoke-test.mjs
```

Скрипт заведёт анонимного пользователя, импортирует тестовый плейлист Deezer,
соберёт ленту, свайпнет пару карточек и напечатает галочки по каждому шагу.
Занимает около минуты. Если здесь всё зелёное — приложение точно заработает,
и любые дальнейшие проблемы будут уже на стороне телефона или сети.

Типичные ответы при ошибке:

* `сеть недоступна` — опечатка в URL.
* `Invalid API key` — скопирован не тот ключ или он обрезан.
* `Anonymous sign-ins are disabled` или `Signups not allowed` — не включены
  анонимные входы, шаг 1.3.

## Часть 2. Приложение (~3 минуты)

### 2.1. На компьютере

Нужен [Node.js](https://nodejs.org) версии 18 или новее. Проверить: `node -v`.

```bash
cd musicswipe/mobile
npm install
cp .env.example .env
```

Откройте `.env` любым редактором и подставьте значения из шага 1.4:

```
EXPO_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

### 2.2. На телефоне

Установите из App Store приложение **Expo Go** (издатель — Expo).
Открывать его прямо сейчас не нужно.

### 2.3. Запустить

```bash
npx expo start
```

В терминале появится QR-код и под ним строки вида:

```
› Metro waiting on exp://192.168.1.42:8081
› Scan the QR code above with Expo Go (Android) or the Camera app (iOS)

› Press r │ reload app
› Press m │ toggle menu
```

### 2.4. Что сканировать

**QR-код в окне терминала** — тот, что напечатан прямо над этими строками.

На iPhone его сканируют **штатным приложением «Камера»**, а не Expo Go:

1. Откройте «Камеру» и наведите на QR-код в терминале.
2. Сверху появится жёлтый баннер «Открыть в Expo Go» — нажмите на него.
3. Expo Go откроется сам и начнёт загружать приложение. Первый раз это
   занимает 10–30 секунд, дальше быстрее.

Готово — на экране онбординг MusicSwipe.

## Если не открывается

**Баннер не появляется при наведении камеры.** Убедитесь, что Expo Go уже
установлен: без него iOS не знает, чем открыть ссылку `exp://`.

**«Something went wrong» или бесконечная загрузка.** Почти всегда телефон
и компьютер в разных сетях. Проверьте, что оба на одном Wi-Fi (телефон не на
мобильном интернете, компьютер не через VPN и не по кабелю в другую подсеть).

**Сеть всё равно не пускает** — гостевой Wi-Fi часто изолирует устройства друг
от друга. Обходится туннелем:

```bash
npx expo start --tunnel
```

Работает через серверы Expo, поэтому годится даже когда телефон в мобильной
сети. Чуть медленнее.

**Совсем без QR.** В Expo Go на главном экране есть поле **Enter URL manually** —
введите адрес, который терминал напечатал после `Metro waiting on`, например
`exp://192.168.1.42:8081`.

**Приложение открылось, но пишет «не настроено».** Значит, `.env` не подхватился.
Проверьте, что файл называется ровно `.env`, лежит в папке `mobile`, а переменные
начинаются с `EXPO_PUBLIC_`. После правки `.env` нужно перезапустить `expo start`:
эти значения подставляются при сборке бандла, на лету не обновляются.

**Вход не работает, кнопка «Продолжить без регистрации» ругается.** Не включены
анонимные входы — шаг 1.3.

## Дальше

* **Правки в коде** подхватываются сами: сохранили файл — приложение
  перезагрузилось. Принудительно — клавиша `r` в терминале.
* **Меню разработчика** на телефоне — потрясти устройство или клавиша `m`
  в терминале.
* **Первый плейлист:** проще всего начать со ссылки на Deezer — он работает
  без каких-либо ключей платформ. Например
  `https://www.deezer.com/playlist/1313621735`. Spotify, Apple Music, YouTube,
  Яндекс и SoundCloud тоже поддерживаются, подробности в [README](README.md).
* **Импорт идёт 20–40 секунд** — это нормально, приложение в это время
  показывает стадии разбора.
