# MusicSwipe — Tinder для музыки

Мобильное приложение: пользователь присылает ссылку на свой плейлист с любой
платформы, приложение разбирает его, строит вкусовой профиль и выдаёт ленту
рекомендаций, которую листают свайпами — вправо «нравится», влево «мимо»,
вверх «в избранное». Каждая карточка проигрывает 30-секундный фрагмент трека.

* **Приложение**: Expo (React Native) + TypeScript. Ставится на iPhone через
  Expo Go за минуту — без Mac, Xcode и подписи.
* **Бэкенд**: Supabase — Postgres с RLS, GoTrue для входа, Edge Functions (Deno)
  для импорта плейлистов и подбора рекомендаций.

```
musicswipe/
├── mobile/                 Приложение Expo — основной клиент
│   ├── app/                Экраны (файловая маршрутизация expo-router)
│   ├── components/         Карточка, плеер, общие элементы
│   ├── hooks/              Колода и проигрыватель превью
│   └── lib/                Supabase, доступ к данным, тема
├── ios/                    Исходный нативный клиент на Swift + SwiftUI
│   └── ...                 Работает, но для установки нужен Mac с Xcode 16+
└── supabase/
    ├── migrations/         Схема БД, RLS, RPC
    ├── functions/          Edge Functions
    └── scripts/            Сквозная проверка бэкенда
```

Оба клиента ходят в один и тот же бэкенд и умеют одно и то же. Swift-версия
оставлена как есть: она полностью рабочая, но требует Mac, поэтому основной
клиент теперь `mobile/`.

## Как это работает

### 1. Импорт плейлиста

`POST /functions/v1/import-playlist { url }`

Функция определяет платформу по ссылке и забирает список треков:

| Платформа | Без ключей | С ключом |
|---|---|---|
| Deezer | публичный API | — |
| Spotify | разбор embed-страницы (до 100 треков) | Web API, `SPOTIFY_CLIENT_ID` + `SPOTIFY_CLIENT_SECRET` |
| Apple Music | разбор публичной страницы | Apple Music API, `APPLE_MUSIC_DEVELOPER_TOKEN` |
| YouTube / YouTube Music | разбор `ytInitialData` | Data API v3, `YOUTUBE_API_KEY` |
| Яндекс Музыка | эндпоинт веб-плеера | — |
| SoundCloud | client_id достаётся со страницы | `SOUNDCLOUD_CLIENT_ID` |

Разбор публичных страниц — запасной путь: он не видит приватные плейлисты
и ломается при редизайне сервиса. Для продакшена ключи стоит прописать.

### 2. Нормализация каталога

Разные платформы отдают разные поля, поэтому все треки сопоставляются
с каталогом **Deezer**: у него открытый API без ключей, 30-секундные превью
и жанры на уровне альбома. Совпадение ищется по паре «исполнитель + название»
с оценкой похожести по токенам и сверкой длительности.

Результат ложится в общий справочник `tracks` / `artists` — он один на всех
пользователей, поэтому популярные треки сопоставляются один раз.

### 3. Вкусовой профиль

Из распознанных треков считаются веса жанров, исполнителей и десятилетий плюс
средний темп и год (`taste_profiles`). Веса нормируются к максимуму, поэтому
плейлист на 20 и на 500 треков дают сопоставимые по величине значения.

Дальше профиль живёт сам: триггер `apply_swipe_feedback` двигает веса на каждом
свайпе (+1 за лайк, +2 за суперлайк, −0.6 за пропуск).

### 4. Рекомендации

`POST /functions/v1/recommend` наполняет очередь `recommendations` в два прохода:

1. **Кандидаты.** Для опорных исполнителей (из плейлиста и лайков) берутся
   похожие исполнители и их топовые треки, для любимых жанров — чарты.
2. **Отбор.** Лучшие по предварительной оценке кандидаты дообогащаются
   жанрами и годом выпуска, после чего считается итоговый скор:

   ```
   0.38 · совпадение жанров
 + 0.27 · близость исполнителя
 + 0.12 · десятилетие
 + 0.13 · популярность
 + 0.05 · близость темпа
 + случайная добавка для разнообразия
   ```

Треки из исходного плейлиста и уже оценённые в ленту не попадают — задача
приложения показывать новое. На одного исполнителя приходится не больше двух
карточек подряд.

Клиент читает готовую колоду через RPC `get_deck()` и подгружает следующую
порцию, когда карточек остаётся меньше пяти.

## Запуск

### Шаг 1. Проект Supabase

Создайте проект на [supabase.com](https://supabase.com) и примените миграцию:

```bash
npm install -g supabase                # или brew install supabase/tap/supabase
cd musicswipe
supabase link --project-ref <ваш-ref>
supabase db push
```

Локально то же самое делается через `supabase start && supabase db reset`.

### Шаг 2. Настройки аутентификации

В панели: **Authentication → Providers → Email** — включить.
Для входа без регистрации: **Authentication → Sign In / Providers →
Anonymous sign-ins** — включить.

Подтверждение почты по ссылке в мобильном онбординге только мешает; если
оставите его включённым, после регистрации приложение попросит подтвердить
адрес и войти заново.

### Шаг 3. Edge Functions

```bash
supabase functions deploy import-playlist
supabase functions deploy recommend
supabase functions deploy rebuild-profile
```

Ключи платформ (все необязательные, см. таблицу выше):

```bash
cp supabase/.env.example supabase/.env   # заполнить нужное
supabase secrets set --env-file supabase/.env
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` платформа подставляет сама.

### Шаг 4. Приложение

```bash
cd mobile
npm install
cp .env.example .env      # подставить URL проекта и anon-ключ
npx expo start
```

Значения берутся из Supabase → Project Settings → API. Нужен именно **anon**-ключ:
`service_role` обходит RLS, в приложении ему не место. Если `.env` нет,
приложение покажет экран с инструкцией вместо пустого окна.

`npx expo start` печатает QR-код. Установите на iPhone **Expo Go** из App Store,
отсканируйте код камерой — приложение откроется на телефоне. Ни Mac, ни Xcode,
ни подписи не нужно; правки в коде подхватываются на лету.

Телефон и компьютер должны быть в одной сети. Если сеть не пускает (гостевой
Wi-Fi, корпоративный VPN), помогает туннель: `npx expo start --tunnel`.

Переменные с префиксом `EXPO_PUBLIC_` подставляются на этапе сборки бандла,
поэтому после правки `.env` перезапустите `expo start`.

### Шаг 4-бис. Нативный клиент на Swift (необязательно)

В `ios/` лежит исходная версия на SwiftUI. Она равнозначна по функциональности
и ходит в тот же бэкенд, но для установки нужен Mac с Xcode 16+:

```bash
cd ios
cp MusicSwipe/Core/Config/Supabase.example.plist MusicSwipe/Core/Config/Supabase.plist
open MusicSwipe.xcodeproj
```

Проект использует синхронизированные группы Xcode: новые файлы в папке
`MusicSwipe/` подхватываются автоматически, править `project.pbxproj` не нужно.

## Тестирование

### Локально, без телефона и без сети

Логика Edge Functions — разбор ссылок, разбор заголовков роликов, извлечение
данных из HTML-страниц, построение вкусового профиля:

```bash
deno test supabase/functions/
```

Приложение — типы и сборка бандла. Metro собирает iOS-бандл и на Linux,
так что ошибки импортов и структуры маршрутов ловятся без macOS:

```bash
cd mobile
npm ci
npx tsc --noEmit
npx expo export --platform ios --output-dir dist
```

### Сквозная проверка бэкенда (нужен живой проект Supabase)

Скрипт проходит весь путь приложения — вход, импорт, лента, свайпы, лайки,
догрузка — и проверяет инварианты, на которых держится экран свайпов:
у всех карточек есть превью, дубликатов нет, на исполнителя не больше двух
карточек, оценённые треки в ленту не возвращаются, без токена чужие данные
не читаются.

```bash
SUPABASE_URL=https://xxx.supabase.co \
SUPABASE_ANON_KEY=eyJ... \
node supabase/scripts/smoke-test.mjs "https://www.deezer.com/playlist/1313621735"
```

Нужен Node 18+. По умолчанию заводится анонимный пользователь; для входа
обычным аккаунтом задайте `TEST_EMAIL` и `TEST_PASSWORD`. Скрипт возвращает
ненулевой код выхода при любой непройденной проверке, так что его можно
поставить в CI.

Ту же проверку удобно гонять против локального стека:

```bash
supabase start
supabase functions serve --env-file supabase/.env   # в отдельном терминале
SUPABASE_URL=http://127.0.0.1:54321 SUPABASE_ANON_KEY=<ключ из вывода supabase start> \
  node supabase/scripts/smoke-test.mjs
```

Что происходит внутри, видно в логах: `supabase functions logs import-playlist`
для облака или вывод `functions serve` локально.

### CI

`.github/workflows/musicswipe.yml`. Приложение Expo проверяется целиком
на бесплатном ubuntu-раннере; macOS нужен только для Swift-версии:

| Задача | Раннер | Что делает |
|---|---|---|
| `logic` | ubuntu | `deno test` + `deno check` |
| `mobile` | ubuntu | типы и сборка бандла Expo |
| `backend` | ubuntu | smoke-тест против живого проекта |
| `ios` | macos-15 | `xcodebuild` Swift-версии, симулятор, скриншот |
| `ipa` | macos-15 | неподписанный `.ipa` (только по кнопке) |

Задачи `ios` и `backend` подхватывают секреты репозитория `SUPABASE_URL`
и `SUPABASE_ANON_KEY`, если они заданы: тогда в симуляторе будет экран входа,
а не заглушка «приложение не настроено». Без секретов сборка всё равно
проходит. Ссылку на тестовый плейлист можно задать переменной репозитория
`TEST_PLAYLIST_URL`.

Минуты macOS в бесплатном тарифе расходуются с коэффициентом ×10, так что
на приватном репозитории это примерно 40 сборок в месяц. Запускать вручную —
через **Actions → MusicSwipe → Run workflow**.

### Установка на свой iPhone

Через **Expo Go** — минута и без единого требования к железу:

1. Поставьте Expo Go из App Store.
2. `cd mobile && npx expo start`.
3. Отсканируйте QR-код камерой телефона.

Никакой подписи, никакого семидневного срока, перезагрузка по сохранению файла.
Так же можно дать потестировать другим: `npx expo start --tunnel` выдаёт ссылку,
которая работает из любой сети.

Ограничение у Expo Go одно: он умеет запускать только те нативные модули,
которые в него уже вшиты. Всё, что использует это приложение (звук, тактильная
отдача, Keychain, изображения), — вшито.

**Отдельное приложение с иконкой на экране «Домой»** делается через EAS Build:
сборка идёт в облаке Expo, Mac по-прежнему не нужен.

```bash
npm install -g eas-cli
eas login
eas build --platform ios --profile preview
```

Для сборки под устройство нужен платный Apple Developer ($99/год) — Apple
не выдаёт профили для установки на устройство иначе. Бесплатная альтернатива:
`eas build --platform ios --profile preview --local` на чужом Mac, либо
симулятор-сборка (`"simulator": true`), которая ставится только в симулятор.

**Важно про бэкенд.** С телефона не виден локальный Supabase на
`127.0.0.1:54321` — в `.env` должен быть адрес облачного проекта. Если очень
нужен локальный, укажите LAN-адрес компьютера и учтите, что iOS по умолчанию
запрещает `http://`.

### Нативный клиент на Swift: установка на iPhone

Актуально, только если вы собираете версию из `ios/`. Нужен Mac: в Xcode
поставить свою команду в **Signing & Capabilities**, поменять Bundle Identifier
на уникальный, подключить телефон кабелем и нажать Run. На iPhone включить
**Настройки → Конфиденциальность и безопасность → Режим разработчика**
и доверить сертификату в **Настройки → Основные → VPN и управление устройством**.
Бесплатная подпись живёт 7 дней.

Без Mac: задача `ipa` в CI собирает неподписанный `.ipa`, который подписывается
вашим Apple ID через Sideloadly или AltStore с Windows или Linux.

### Приложение вручную

На своём телефоне через Expo Go:

1. Первый запуск без `.env` — должен открыться экран с инструкцией,
   а не пустое окно.
2. «Продолжить без регистрации» → экран импорта.
3. Вставить ссылку на плейлист → под полем появляется определённая платформа,
   во время импорта идут стадии, в конце — разбор вкуса и число карточек.
4. Лента: превью играет само, кнопка паузы работает, свайпы во все три
   стороны, штампы проявляются при перетаскивании.
5. Свернуть приложение — звук останавливается.
6. Вкладка «Любимое» — свайпнутые вправо треки на месте, превью играет,
   стрелка открывает трек на Deezer.
7. Вкладка «Профиль» — жанры на диаграмме, плейлист со статусом «готово»,
   «Пересобрать профиль» отрабатывает без ошибки.
8. Полностью закрыть и открыть заново — сессия восстанавливается из Keychain,
   вход заново не требуется.

## Устройство приложения

```
mobile/
├── app/                    Экраны (файловая маршрутизация expo-router)
│   ├── _layout.tsx         Провайдеры и развилка вход → импорт → лента
│   ├── sign-in.tsx         Вход, регистрация, гостевой режим
│   ├── import.tsx          Импорт плейлиста и разбор результата
│   └── (tabs)/             Лента, Любимое, Профиль
├── components/             Карточка, полоса воспроизведения, общие элементы
├── hooks/
│   ├── useDeck.ts          Колода: загрузка, свайпы, догрузка
│   └── usePreviewPlayer.ts Превью: автозапуск, зацикливание, учёт прослушивания
└── lib/
    ├── supabase.ts         Клиент и единый разбор ошибок трёх сервисов
    ├── api.ts              Доступ к данным (RPC и Edge Functions)
    ├── auth.tsx            Сессия
    ├── onboarding.tsx      Есть ли у пользователя разобранный плейлист
    └── theme.ts            Цвета и размеры
```

Сессия лежит в Keychain через `expo-secure-store`. У него ограничение примерно
в 2 КБ на значение, а пара access- и refresh-токенов в него не влезает, поэтому
`lib/secure-storage.ts` режет значение на куски. Обычный AsyncStorage хранил бы
токены в файле, попадающем в резервные копии в открытом виде.

Свайп применяется к экрану сразу, а запрос уходит следом: листание не должно
ждать сеть. Если запрос не дошёл, сервер просто не узнает об оценке — колода
фильтруется по уже оценённым трекам на его стороне, так что худшее последствие
это повторный показ карточки.

Вся выборка данных идёт через RPC (`get_deck`, `record_swipe`, `liked_tracks`,
`taste_summary`), поэтому клиент не знает ни про join'ы, ни про фильтры —
за изоляцию данных отвечает RLS, а `auth.uid()` подставляется на сервере.

Жест карточки сделан на `Animated` и `PanResponder` из ядра React Native,
без Reanimated и Gesture Handler: для колоды этого достаточно, а зависимостей
и возни с конфигурацией Babel меньше.

## Что стоит знать

* **Ограничения объёма.** Из плейлиста сохраняется до 500 треков, для анализа
  берётся равномерная выборка из 100 — разбор упирается во внешнее API,
  и на вкусовой профиль выборка влияет не хуже полного списка. Импорт
  занимает 20–40 секунд, экран показывает стадии.
* **Треки без превью** в ленту не попадают: карточку, которую нельзя послушать,
  свайпать не по чему.
* **Гостевой аккаунт** полноценный с точки зрения БД (свой `user_id`, свои
  рекомендации), но привязки к почте у него нет — на другом устройстве данные
  не восстановить.
* **Разбор публичных страниц** Spotify, Apple Music и YouTube держится на
  структуре их вёрстки. Ключи из таблицы выше убирают эту хрупкость.
* **Права на музыку.** В приложении играют только официальные превью-фрагменты
  из каталога Deezer, полные треки не хранятся и не проксируются.
