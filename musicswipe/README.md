# MusicSwipe — Tinder для музыки

Нативное приложение для iOS: пользователь присылает ссылку на свой плейлист
с любой платформы, приложение разбирает его, строит вкусовой профиль и выдаёт
ленту рекомендаций, которую листают свайпами — вправо «нравится», влево «мимо»,
вверх «в избранное». Каждая карточка проигрывает 30-секундный фрагмент трека.

* **iOS**: Swift 5 + SwiftUI, минимальная версия iOS 17, без сторонних зависимостей.
* **Бэкенд**: Supabase — Postgres с RLS, GoTrue для входа, Edge Functions (Deno)
  для импорта плейлистов и подбора рекомендаций.

```
musicswipe/
├── ios/                    Приложение (открывается в Xcode 16+)
│   ├── MusicSwipe.xcodeproj
│   ├── MusicSwipe/         Исходники
│   └── project.yml         Описание проекта для XcodeGen (запасной вариант)
└── supabase/
    ├── migrations/         Схема БД, RLS, RPC
    ├── functions/          Edge Functions
    └── config.toml
```

## Как это работает

### 1. Импорт плейлиста

`POST /functions/v1/import-playlist { url }`

Функция определяет платформу по ссылке и забирает список треков:

| Платформа | Без ключей | С ключом |
|---|---|---|
| Deezer | публичный API | — |
| Spotify | разбор embed-страницы (до 100 треков) | Web API, `SPOTIFY_CLIENT_ID` + `SPOTIFY_CLIENT_SECRET` |
| Apple Music | разбор публичной страницы | Apple Music API, `APPLE_MUSIC_DEVELOPER_TOKEN` |
| YouTube / YouTube Music | разбор `ytInitialData` | Data API v3, `YOUTUBE_API_KEY` |
| Яндекс Музыка | эндпоинт веб-плеера | — |
| SoundCloud | client_id достаётся со страницы | `SOUNDCLOUD_CLIENT_ID` |

Разбор публичных страниц — запасной путь: он не видит приватные плейлисты
и ломается при редизайне сервиса. Для продакшена ключи стоит прописать.

### 2. Нормализация каталога

Разные платформы отдают разные поля, поэтому все треки сопоставляются
с каталогом **Deezer**: у него открытый API без ключей, 30-секундные превью
и жанры на уровне альбома. Совпадение ищется по паре «исполнитель + название»
с оценкой похожести по токенам и сверкой длительности.

Результат ложится в общий справочник `tracks` / `artists` — он один на всех
пользователей, поэтому популярные треки сопоставляются один раз.

### 3. Вкусовой профиль

Из распознанных треков считаются веса жанров, исполнителей и десятилетий плюс
средний темп и год (`taste_profiles`). Веса нормируются к максимуму, поэтому
плейлист на 20 и на 500 треков дают сопоставимые по величине значения.

Дальше профиль живёт сам: триггер `apply_swipe_feedback` двигает веса на каждом
свайпе (+1 за лайк, +2 за суперлайк, −0.6 за пропуск).

### 4. Рекомендации

`POST /functions/v1/recommend` наполняет очередь `recommendations` в два прохода:

1. **Кандидаты.** Для опорных исполнителей (из плейлиста и лайков) берутся
   похожие исполнители и их топовые треки, для любимых жанров — чарты.
2. **Отбор.** Лучшие по предварительной оценке кандидаты дообогащаются
   жанрами и годом выпуска, после чего считается итоговый скор:

   ```
   0.38 · совпадение жанров
 + 0.27 · близость исполнителя
 + 0.12 · десятилетие
 + 0.13 · популярность
 + 0.05 · близость темпа
 + случайная добавка для разнообразия
   ```

Треки из исходного плейлиста и уже оценённые в ленту не попадают — задача
приложения показывать новое. На одного исполнителя приходится не больше двух
карточек подряд.

Клиент читает готовую колоду через RPC `get_deck()` и подгружает следующую
порцию, когда карточек остаётся меньше пяти.

## Запуск

### Шаг 1. Проект Supabase

Создайте проект на [supabase.com](https://supabase.com) и примените миграцию:

```bash
npm install -g supabase                # или brew install supabase/tap/supabase
cd musicswipe
supabase link --project-ref <ваш-ref>
supabase db push
```

Локально то же самое делается через `supabase start && supabase db reset`.

### Шаг 2. Настройки аутентификации

В панели: **Authentication → Providers → Email** — включить.
Для входа без регистрации: **Authentication → Sign In / Providers →
Anonymous sign-ins** — включить.

Подтверждение почты по ссылке в мобильном онбординге только мешает; если
оставите его включённым, после регистрации приложение попросит подтвердить
адрес и войти заново.

### Шаг 3. Edge Functions

```bash
supabase functions deploy import-playlist
supabase functions deploy recommend
supabase functions deploy rebuild-profile
```

Ключи платформ (все необязательные, см. таблицу выше):

```bash
cp supabase/.env.example supabase/.env   # заполнить нужное
supabase secrets set --env-file supabase/.env
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` платформа подставляет сама.

### Шаг 4. iOS

```bash
cd ios
cp MusicSwipe/Core/Config/Supabase.example.plist MusicSwipe/Core/Config/Supabase.plist
```

В `Supabase.plist` укажите URL проекта и **anon**-ключ
(Supabase → Project Settings → API). `service_role` в приложение класть нельзя:
он обходит RLS.

Откройте `MusicSwipe.xcodeproj` в Xcode 16 или новее, выберите симулятор
и запустите. Если файла с ключами нет, приложение покажет экран с инструкцией
вместо пустого окна.

Проект использует синхронизированные группы Xcode: новые файлы в папке
`MusicSwipe/` подхватываются автоматически, править `project.pbxproj` не нужно.
Если файл проекта всё же понадобится пересобрать — `xcodegen generate`
по описанию `project.yml`.

## Устройство приложения

```
MusicSwipe/
├── App/            Точка входа, развилка экранов, таббар
├── Core/
│   ├── Config/     Чтение Supabase.plist
│   ├── Supabase/   Клиент (GoTrue + PostgREST + Functions), репозиторий данных
│   ├── Models/     Модели ответов
│   ├── Audio/      Проигрыватель превью
│   └── UI/         Тема и переиспользуемые компоненты
└── Features/
    ├── Auth/       Вход, регистрация, гостевой режим
    ├── Import/     Импорт плейлиста и разбор результата
    ├── Swipe/      Колода карточек
    ├── Likes/      Понравившееся
    └── Profile/    Вкусовой профиль, плейлисты, выход
```

Клиент Supabase написан на `URLSession` вместо готового SDK: приложению нужны
только вход, вызов RPC и вызов Edge Functions — это несколько сотен строк,
зато сборка не зависит от разрешения пакетов.

Токены хранятся в Keychain, обновляются заранее (за минуту до истечения),
и параллельные запросы ждут один общий refresh, чтобы не сжечь токен при
ротации.

Вся выборка данных идёт через RPC (`get_deck`, `record_swipe`, `liked_tracks`,
`taste_summary`), поэтому клиент не знает ни про join'ы, ни про фильтры —
за изоляцию данных отвечает RLS, а `auth.uid()` подставляется на сервере.

## Что стоит знать

* **Ограничения объёма.** Из плейлиста сохраняется до 500 треков, для анализа
  берётся равномерная выборка из 100 — разбор упирается во внешнее API,
  и на вкусовой профиль выборка влияет не хуже полного списка. Импорт
  занимает 20–40 секунд, экран показывает стадии.
* **Треки без превью** в ленту не попадают: карточку, которую нельзя послушать,
  свайпать не по чему.
* **Гостевой аккаунт** полноценный с точки зрения БД (свой `user_id`, свои
  рекомендации), но привязки к почте у него нет — на другом устройстве данные
  не восстановить.
* **Разбор публичных страниц** Spotify, Apple Music и YouTube держится на
  структуре их вёрстки. Ключи из таблицы выше убирают эту хрупкость.
* **Права на музыку.** В приложении играют только официальные превью-фрагменты
  из каталога Deezer, полные треки не хранятся и не проксируются.
